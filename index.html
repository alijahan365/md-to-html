Flex Scanner Rules (`lexer.l`)

%{
#include "parser.tab.h"
%}
%option noyywrap yylineno

%%
"^# "[^\n]+        { yylval.str = strdup(yytext+2); return HEADER1; }
"^## "[^\n]+       { yylval.str = strdup(yytext+3); return HEADER2; }
"^### "[^\n]+      { yylval.str = strdup(yytext+4); return HEADER3; }
"**"[^\*\n]+"**"   { yylval.str = strdup(yytext); return BOLD; }
"*"[^\*\n]+"*"     { yylval.str = strdup(yytext); return ITALIC; }
"^"- "[^\n]+       { yylval.str = strdup(yytext+2); return UNORDERED_LIST; }
"^[0-9]+\. "[^\n]+ { yylval.str = strdup(yytext); return ORDERED_LIST; }
"["[^\n]+"]("[^\n]+")" { yylval.str = strdup(yytext); return LINK; }
\n                 { return NEWLINE; }
.                  { return TEXT; }
%%

Bison LALR Grammar Specification (`parser.y`)

%{
#include 
void yyerror(const char *s);
int yylex();
%}
%union { char *str; }
%token <str> HEADER1 HEADER2 HEADER3 BOLD ITALIC UNORDERED_LIST ORDERED_LIST LINK TEXT NEWLINE

%%
doc: elements ;
elements: elements element | element ;
element: HEADER1 { printf("<h1>%s</h1>\n", $1); }
       | HEADER2 { printf("<h2>%s</h2>\n", $1); }
       | HEADER3 { printf("<h3>%s</h3>\n", $1); }
       | UNORDERED_LIST { printf("<li>%s</li>\n", $1); }
       | BOLD { printf("<strong>%s</strong>", $1); }
       | ITALIC { printf("<em>%s</em>", $1); }
       ;
%%

4-Phase Compiler Breakdown

Detailed technical specification of each compiler phase in our handwritten C engine & web studio implementation.

Phase 1

Lexical Scanner (`lexer.c` / `lexer.l`)

Scans input Markdown source code character-by-character. Emits 14 token types (`HEADER1..3`, `BOLD`, `ITALIC`, `UNORDERED_LIST`, `ORDERED_LIST`, `LINK_START/MID/END`, `TEXT`, `NEWLINE`, `BLANK_LINE`, `EOF`). Maintains exact `line_number` and `column_number` positions for every token.

Phase 2

Syntax Parser (`parser.c` / `parser.y`)

Constructs an Abstract Syntax Tree (AST) using a Top-Down Recursive Descent approach in C and formal LALR Context-Free Grammar rules in Bison. Creates tree nodes for Document structural blocks, Headings, Paragraphs, Lists, and Inline Formats.

Phase 3

Symbol Table & Semantic Analyzer (`symbol_table.c` & `semantic.c`)

Populates a dynamic symbol table containing all document Headings (with auto-slugified anchor IDs) and Hyperlinks. Validates semantic integrity: flags empty headings, missing link targets, and duplicate heading anchor ID collisions.

Phase 4

HTML Code Generator (`html_generator.c`)

Performs a post-order traversal on the AST to emit clean, standard HTML5 elements (<h1>..<h3>, <p>, <ul>, <ol>, <li>, <strong>, <em>, <a>).

CEP (Complex Engineering Problem) & Architecture

CEP 5-Point Requirement Alignment

CEP Requirement Project Implementation & Technical Defense
1. Depth of Knowledge Applies core compiler concepts: character tokenization, LL/LALR syntax tree parsing, dynamic symbol table management, and semantic verification.
2. Conflicting Requirements Balances handwritten recursive descent parsing simplicity with formal Flex/Bison LALR grammar specifications and line/column error tracking.
3. Depth of Analysis Evaluates Markdown grammar ambiguities (inline formatting vs list blocks) and provides precise source position diagnostics.
4. Multiple Components Integrates 5 connected compiler modules: Lexer, Parser, Symbol Table, Semantic Analyzer, and Target HTML Code Generator.
5. Unfamiliar Issues Handles edge cases: unclosed Markdown delimiters, missing link target URLs, empty headers, and duplicate anchor collisions.
